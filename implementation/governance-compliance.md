# Website Governance Implementation

## Objective

Create a repeatable process for maintaining website quality, accessibility, content accuracy, and search visibility after the initial optimization work.

Rather than treating the project as a one-time website cleanup, I developed a structured approach for identifying, evaluating, categorizing, resolving, and measuring website issues.

## Governance Framework

The project combined established accessibility guidance with website evaluation and auditing tools.

### ♿ Web Content Accessibility Guidelines (WCAG) 2.1

WCAG 2.1 provided the accessibility guidelines used to evaluate website content and identify accessibility improvement opportunities.

[WCAG 2.1 — W3C](https://www.w3.org/TR/WCAG21/)

### 🔎 WAVE Web Accessibility Evaluation Tool

WAVE was used to evaluate website pages for accessibility-related issues and identify areas requiring further review.

[WAVE Web Accessibility Evaluation Tool](https://wave.webaim.org/)

WAVE was used as an evaluation aid rather than as a standalone measure of accessibility compliance. Accessibility also requires human review and contextual evaluation.

### 🕷️ Screaming Frog SEO Spider

Screaming Frog SEO Spider was used to crawl website pages and identify SEO and technical discoverability issues.

It supported the review of page-level SEO elements and other factors affecting search visibility.

[Screaming Frog SEO Spider](https://www.screamingfrog.co.uk/seo-spider/)

## Governance Process

The project followed a continuous improvement cycle:

**Identify → Evaluate → Categorize → Prioritize → Resolve → Measure → Review**

### 1. Identify

Website pages were reviewed using accessibility tools, SEO auditing tools, and manual review.

### 2. Evaluate

Issues were evaluated using the appropriate accessibility guidance, audit criteria, or content-quality considerations.

### 3. Categorize

Issues were organized into categories such as:

- Content
- Accessibility
- Readability
- SEO / Discoverability
- Other

### 4. Prioritize

Issues were prioritized based on their potential impact on accuracy, usability, accessibility, and discoverability.

### 5. Resolve

Applicable issues were addressed through CMS editing, content updates, SEO optimization, and accessibility improvements.

### 6. Measure

A KPI dashboard was created to track issue completion, category-level progress, and SEO performance.

### 7. Review

The process supports continued website review rather than treating optimization as a one-time project.

## Governance & Measurement

The KPI dashboard provided visibility into project progress and allowed website improvements to be tracked quantitatively.

### Project Results

- **84 issues identified**
- **80 issues completed**
- **4 issues in progress**
- **5 pages audited**
- **16 percentage-point average SEO improvement**

The dashboard also tracked issue completion by category, including content, accessibility, readability, and other website quality issues.

## Scope

The governance and remediation work focused on frontend/CMS editing, website content, accessibility, SEO, and structured website review.

The project did not include backend development or code-level remediation outside of the available CMS environment.
